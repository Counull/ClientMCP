# 远程诊断连接

来源：2026-09-30、2026-10-17 项目讨论。本文记录需求、职责与连接设计；实际实现和已执行验证以 [当前状态](status.md) 为准。
术语见 [CONTEXT.md](../CONTEXT.md)。

我们要让 AI 通过 C# 反射检查和操作正在运行的 Unity 客户端，覆盖开发阶段和已分发程序。ClientMCP 提供通用反射元操作；AI 在游戏外编写并执行脚本，组合这些操作完成具体任务。业务含义属于调用方，包本身不认识任何消费项目的玩法或功能。

## 开发阶段首轮需求

- 游戏保持运行，AI 通过外部脚本读取和修改运行时变量、调整允许访问的运行环境，并调用已有代码；接入完成后的操作不依赖暂停游戏或重新编译 Unity 脚本。
- 至少能在 Codex 中显示变量的类型、当前值、对象引用和操作结果；显示方式不以另建游戏内调试面板为前提。
- 实际操作由 ClientMCP 的运行时连接与反射执行完成，不依赖 Rider、Unity Editor MCP 或附加调试器。
- 外部脚本负责组合定位对象、构造实例、设置成员和调用方法等步骤。例如向某个集合添加对象所需的类型、参数与调用顺序，由 AI 根据消费项目的实际代码决定。
- 不要求消费项目为每项业务注册调试命令或编写 ClientMCP 专用接口；复用已有方法还是组合更基础的反射操作，由调用方按实际对象结构决定。

## 与消费工程的迭代方式

- 在本项目讨论能力演进、设计和实现，通用源码保留在 UPM 包中。开发期间建议由消费工程通过 UPM 本地依赖共同使用同一份包源码。
- 每项功能实现并完成适当自测后，可交给用户已授权的消费工程进行真实运行测试；交接包含包版本或源码状态、实际变更、操作示例、已执行检查与待验证内容。
- 消费工程的业务脚本、私有类型、实际测试数据和日志留在消费工程。公开仓库只沉淀通用实现、抽象示例和可公开的验证结论。
- 消费工程发现的通用问题回到本项目修正。功能尚未实现时，不交接为可测试的新版本。

## 通用反射接口的设计目标

- 调试接口数量不随业务功能数量增长；不为背包、任务、战斗等模块分别编写查询接口。
- AI 根据实际类型和对象结构选择操作步骤，插件负责执行通用反射操作，不判断业务含义。
- 元操作覆盖：查找类型与定位对象、枚举成员及签名、读取和设置字段或属性、调用构造函数创建对象、调用实例或静态方法。集合操作复用相应类型的方法，不增加业务专用接口；请求与返回格式见 [外部脚本说明](../Tools/README.md)。
- 新字段、新方法和新类型在可定位、反射信息保留的前提下应能直接操作，无需修改插件或逐个业务编写适配。
- 普通字段读取不隐式执行属性 getter；属性访问、写入、对象构造和方法调用均由调用方显式指定。
- 反射请求须提供 `description`，用简短说明解释当前操作；在统一入口校验后，主线程 Console 记录实际执行说明及成功或失败，状态窗口保留最近请求。说明不从参数或返回值自动展开，MCP 工具 schema 同样声明为必填。
- 通过句柄逐步访问引用，不增加路径表达式语言；参数与返回值共用对象引用格式。重载不猜测，复杂签名由调用方明确参数类型。
- Unity 对象操作在主线程执行；请求处理限制大小与处理量，并区分尚未执行的请求超时和已开始调用的方法，不能假设超时会终止已执行的 C# 方法。

## 首版本机接入

- `ReflectionSession` 只执行反射；`ClientMcpRuntime` 管理运行生命周期和主线程请求；本机 HTTP 与 MCP 入口共用这一个执行器，外部脚本不依赖 Editor 工具。
- 为满足开发阶段的本机操作，接入直接位于 Unity Runtime 内，暂不需要独立桥接进程。`/reflect` 接收通用脚本请求；`/mcp` 提供 MCP Streamable HTTP 的 JSON 响应模式，支持初始化、工具发现与工具调用，不提供独立 SSE 流。
- 默认不监听。Editor 会话中勾选启用菜单后进入 Play，或在 Player 启动时传 `--clientmcp`；宿主也可显式调用启动方法。普通发行包没有启动参数时不开放入口。
- 只绑定 `127.0.0.1`，默认随机端口，所有入口检查随机 Bearer 令牌；同时检查 Host 与 Origin。连接文件只供本机调用方读取，不属于项目资产，不提交或公开。
- 首版是受信任的本机开发入口，允许访问进程中实际保留的类型和公开或非公开成员，不提供反射沙箱或业务权限系统。外部脚本须使用当前会话的句柄；退出运行时释放句柄和监听连接。
- HTTP 报文及并发有上限；主线程每帧限制请求数与处理预算。请求执行前超时会取消排队请求；已经开始的方法不可强制中断。MCP 跨请求取消通知尚不支持，明确返回错误，不承诺撤销。
- 成员查看不执行任意 getter 或 `ToString`；属性访问和方法调用由调用方显式发起。结构值作为副本返回，需要明确写回父成员。开放泛型、ref/out、指针及索引器 get/set 不在首版支持范围；可调用具体访问方法。
- Unity 原生对象遵循引擎创建流程，可反射调用现有工厂、实例化或挂接方法；不通过普通对象构造元操作直接构造它们。发布构建的类型裁剪与 AOT 限制需要按目标平台验证。

## 通用操作计划与缓存

为减少 AI 对同一意图反复探测和逐字段往返，Runtime 在原反射执行器上保存验证过的步骤；不加载业务辅助类，不新增编译器。MCP 使用同一个 `clientmcp_reflect` 工具，以 `op=plan` 的五种动作准备、执行、查回执、列出和释放。完整字段及示例只维护在[使用说明](../Tools/README.md#优先复用已验证的操作计划)。

通用复用规则由 ClientMCP 使用文档和 MCP 提示提供；具体步骤、参数与本地脚本属于消费工程，项目约定只引用通用规则和记录私有入口。缓存步骤，不缓存当前运行值；对象通过本次参数或本次前序结果绑定，计划不能嵌入旧对象句柄。重载后可从消费工程保留的步骤重新准备，不重新编译临时辅助代码。

计划在一个主线程回调内顺序执行，失败停止后续步骤，已经发生的修改不回滚。新意图使用新操作编号，原编号重试或查结果只返回原回执；操作号在执行前保留，部分失败也不会导致前面写入被自动重做。同一编号的不同计划或参数会被拒绝；当前会话最多 32 个计划、128 个操作记录，不自动淘汰，显式释放计划会结束相应去重保证。

本轮不加入跨帧时间轴或任务调度。调用宿主已有非阻塞方法时，只确认反射调用返回；业务异步完成由宿主状态确认。准备耗时、请求往返、操作触发和业务完成分别报告，避免把一次快速返回写成整项演示完成。

## 如何连接内网客户端

采用客户端主动出站连接、服务端复用该连接下发请求的思路。客户端不需要公网 IP，也不需要让路由器把入站端口映射到游戏进程；不以 P2P 打洞或通用内网穿透软件为前提。

```text
Unity 客户端 ──主动建立连接──> 公网服务端 <──标准 MCP── 开发者工具
Unity 客户端 <──同一连接下发请求── 公网服务端 ──返回结果──> 开发者工具
```

前提是客户端网络允许访问服务端，且连接仍然有效。代理、防火墙或移动端挂起仍可能中断连接，需要心跳、断线重连和请求超时；已退出或离线的进程不能接受实时诊断。

## 最小连接方案

- 准则：如非必要，勿增实体。只保留当前需求所需内容，不维护备选方案或提前设计扩展。
- 客户端到服务端：使用 WSS 双向长连接，承载诊断请求和结果；`ws` 只允许 loopback 本地验证，不跳过证书验证。
- 开发者工具到服务端：只提供 HTTPS 上的 MCP Streamable HTTP，不兼容旧版 HTTP+SSE 传输。Streamable HTTP 不等于 HTTP/2，其流式响应仍可使用 SSE。
- 一个服务端程序承载游戏连接与 MCP 接口；当前不增加独立 Web 后台，开发者先通过 Codex 操作。
- 读取与显式写入分别处理；诊断启用开关、实例身份、开发者授权和反射访问范围须在实现前明确。运行实例身份与 MCP 会话身份分开管理。

## 桥接服务端

- 位于仓库根目录 `Server/`，与 Unity 工程 `Project/` 并列；使用 C# / ASP.NET Core，独立启动和部署。
- 一个进程提供 `/mcp` 与 `/client` 两个入口，分别接入开发者工具和游戏实例。路径为当前设计名称。
- 职责保持窄：接入认证、维护在线实例、路由请求与结果，以及处理超时、断线和连接释放。不理解游戏业务，反射执行归客户端，诊断决策归 AI。
- 最小运行状态为一张在线连接表和一张待回复请求表。`instanceId` 定位目标实例，`requestId` 关联请求与回复；断线时结束受影响的请求，释放连接与等待状态。
- 一个服务端连接 N 个游戏实例。`clientmcp_instances` 列出在线实例、版本与连接时间；`clientmcp_reflect` 和 `clientmcp_status` 每次显式传 `instanceId`，没有共享的当前选择状态。实例标识沿用 Runtime 的 `sessionId`，与 MCP HTTP 会话分离；重连不重建反射会话，进程或 Runtime 重启则生成新标识。
- 首版为单运营者模型：客户端接入令牌与开发者令牌独立配置，开发者令牌可操作本服务接入的全部实例。没有逐用户授权、多租户隔离或业务用户身份认证，不把实例名称当作授权依据。
- 当前不增加历史存储或独立监控后台。极简指职责和组件最少，不省略连接生命周期的必要处理。

### 请求与重连

WebSocket 使用 UTF-8 JSON 对象：客户端先发送 `hello`（`instanceId`、`sessionId`、`name`、`unityVersion`、`isEditor`、`processId`），服务端回复 `welcome`。服务端下发 `request`（`requestId`、`command`），客户端返回 `response`（相同 `requestId`、`body`）；`body` 沿用本机 `/reflect` 的成功或失败封装。客户端定期发送 `ping`，服务端返回 `pong`。

待回复请求绑定具体连接，断线即结束等待，旧连接不能完成新连接的请求。中转不自动重发任何反射写入。HTTP 超时或断线不证明已开始的操作没有生效；重试计划应沿用原 `operationId`，或先查 `result`。连接关闭时取消尚未开始执行的客户端请求，无法中断已经开始的宿主方法。

反射能力等同于当前进程中的受信任代码访问。中转令牌不是业务权限白名单；只为受控诊断启用，令牌通过私有环境配置或宿主参数传递，禁止放在 URL、日志或版本库中。

## 启动与接入

服务端需要 .NET 10 SDK（源码构建）或 ASP.NET Core 10 Runtime（运行发布产物）。仓库根目录使用 PowerShell：

```powershell
$env:CLIENTMCP_URL = 'http://127.0.0.1:55707'
$env:CLIENTMCP_DEVELOPER_TOKEN = '<独立随机开发者令牌，至少32字符>'
$env:CLIENTMCP_CLIENT_TOKEN = '<独立随机客户端令牌，至少32字符>'
dotnet run --project Server/ClientMcp.Server.csproj
```

两个令牌必须不同。非 loopback 监听必须配置 HTTPS 和有效的 ASP.NET Core 服务端证书；首版直接由 Kestrel 终止 TLS，不处理转发代理头。出现的 `Origin` 一律拒绝，供原生 MCP 和 Unity 接入使用。默认有 64 个连接、每实例 64 个待回复请求和全局 256 个待回复请求上限；报文限制 1 MiB，JSON 深度限制 64。转发等待 15 秒，注册等待 10 秒，客户端每 10 秒心跳，服务端 45 秒未收到心跳会断开连接。

Unity 宿主在主线程显式启用：

```csharp
ClientMcpRuntime.Start(new ClientMcpOptions
{
    RelayUrl = "wss://<服务主机>/client",
    RelayToken = privateClientToken,
    InstanceName = "诊断实例"
});
```

已启动的 Runtime 使用 `ClientMcpRuntime.ConnectRelay(url, token, instanceName)`；`DisconnectRelay()` 只关闭出站连接，`Stop()` 结束整个反射会话。网络线程不会访问 Unity 对象；实际命令仍进入原有有界主线程队列。`ClientMcpRuntime.GetConnectionStatus()` 和状态工具中的 `connection.relay` 提供出站连接状态，不显示 URL 或令牌。

Player 带 `--clientmcp` 显式启用时，可以通过私有环境变量 `CLIENTMCP_RELAY_URL`、`CLIENTMCP_RELAY_TOKEN`、`CLIENTMCP_INSTANCE_NAME` 配置出站连接。本机测试使用 `ws://127.0.0.1:55707/client`；未显式启用时，环境配置不会自行开启诊断。

Codex 的 HTTP MCP 地址为 `https://<服务主机>/mcp`，认证头为 `Authorization: Bearer <开发者令牌>`。本机测试地址为 `http://127.0.0.1:55707/mcp`，不需要 stdio 进程。工具流程：

1. 调用 `clientmcp_instances`，读取在线实例的 `instanceId`。
2. 调用 `clientmcp_status({"instanceId":"..."})` 取得目标 Runtime 会话信息。
3. 调用 `clientmcp_reflect`，在原有参数中加 `instanceId`；先列已有计划，再进行必要探测或复用。

同一 Runtime 的 loopback 与中转入口共享对象句柄和计划；不同实例的句柄、会话与回执不能混用。MCP HTTP 采用无会话 JSON 响应模式，不发放 `MCP-Session-Id`，GET 返回 405，不提供独立 SSE 流。

传输与路由回归可在仓库根目录运行 `dotnet run --project Server/Tests/ClientMcp.Server.Tests.csproj`。测试链接真实 UPM 出站传输，执行委托使用隔离值；Unity 主线程反射、Player 和公网验证须另外执行，不能以该测试代替。

## 验收顺序

1. 首先验证单个 Unity 运行实例：外部脚本或 MCP 客户端 → 本机 Runtime 接入 → 通用反射执行器；Editor Play 与打包程序使用同一套能力。
2. 在游戏持续运行时，通过外部脚本验证对象定位、成员结构查看、普通字段、私有字段和嵌套字段读取，以及显式写入和运行环境修改后生效。
3. 验证显式属性访问、构造对象、调用实例与静态方法，以及将新对象通过集合方法加入现有结构；检查返回结果与实际运行状态。
4. 给测试组件新增字段和方法并重新打包，不修改诊断插件，确认仍可发现、读取、写入和调用。这是通用能力不随业务增长的关键验证。
5. 首轮使用 Windows Mono；其他目标按实际脚本后端验证，目标为 IL2CPP 时直接验证 IL2CPP 发布包。
6. 本机闭环通过后，再部署到公网并连接两个游戏实例，验证实例选择、路由与断线重连。

当前执行结果和尚未覆盖的部分只维护在 [当前状态](status.md)，不将本机验证写成公网或其他平台通过。
